# TikTok-бот на FadeHost (polling) — готовая проба, без переписывания

Это тот же бот v4 с Koyeb (`app.py` здесь — копия, логика скачивания не менялась),
только транспорт другой: вместо webhook — polling (`polling.py`).
Ничего решать заранее не нужно: это заготовка на случай, если выберешь FadeHost.
Koyeb-бот при этом не трогается, пока ты сам его не остановишь.

## Почему именно FadeHost первым

По исследованию от 28.10.2026 (форумы + страницы хостов, вживую не тестировалось):
- бесплатный polling-бот, заявлено «always on, без сна, без монеты/ежедневных продлений», без карты;
- 256 МБ / 0.25 vCPU / 3 ГБ — меньше RAM, чем на Koyeb (512 МБ), но очередь
  «одно видео за раз» уже защищает от OOM, а 3 ГБ диска — самые щедрые среди бесплатных бот-хостов;
- деплой из GitHub, регионы FR / CA / US / SG;
- подвох: веб-адрес на free спит, поэтому webhook там не работает — только polling.
  Именно поэтому здесь есть `polling.py`, а не webhook.
- подвох №2: Dockerfile/сборка образа — только на платных тарифах, системные пакеты
  самому не поставить. `ffmpeg` на free не подтверждён. Наш код специально качает
  single-file mp4 (`best[ext=mp4]/best`), то есть мердж через ffmpeg ему не нужен,
  но если TikTok отдаст видео и звук отдельными потоками — это вскроется только на живом тесте.

## Запуск (по шагам)

1. Залей эту папку (`app.py`, `polling.py`, `requirements.txt`) в репозиторий на GitHub.
   Токена в коде нет — проверено, он берётся только из переменной окружения.
2. FadeHost → создай бесплатного бота, укажи репозиторий, команду запуска `python polling.py`,
   переменную окружения `BOT_TOKEN` (только в панели, не в коде).
3. Перед первым запуском останови/поставь на паузу сервис на Koyeb.
   `polling.py` при старте сам вызовет `deleteWebhook` (с очисткой очереди апдейтов),
   иначе Telegram не отдаст апдейты через polling, а вернёт 409.
   Если Koyeb не остановить, webhook просто перестанет работать — дубликатов не будет,
   но и Koyeb-бот замолчит.
4. Проверки первого дня (не переезжай, пока не пройдены):
   - `/start` отвечает быстро (polling, а не пробуждение контейнера);
   - реальная ссылка на TikTok скачивается и приходит без водяного знака;
   - короткая ссылка `vm.tiktok.com` / `vt.tiktok.com` тоже работает (код сам её разворачивает);
   - в логах нет `tikwm HTTP ...` с пустым телом — это признак блокировки со стороны IP хоста.
   Если ffmpeg/ IP хоста не подошли — не борись с ним, это и есть ответ теста.

## Назад на Koyeb (если FadeHost не подошёл)

1. Останови бота на FadeHost.
2. Запусти сервис на Koyeb заново.
3. Выполни `set_webhook.sh` из папки `koyeb-tiktok-bot` (он снова поставит webhook
   на адрес Koyeb). UptimeRobot-пингер на `/health` при этом снова актуален.

## Что не изменилось

- Очередь: одно скачивание за раз, остальные ждут.
- Быстрый путь: tikwm → Telegram сам забирает видео по прямой ссылке, без скачивания на хост.
- Запасной путь: yt-dlp, потом скачивание через tikwm.
- Лимит 50 МБ Telegram Bot API: файлы больше 48 МБ не качаются.
- Никаких платных тарифов, карт и триалов для этой пробы не нужно.
